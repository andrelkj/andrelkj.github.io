# Test suite changelog

One entry per merged phase. Each PR lists its commits, and each commit says what changed, why, and how it was verified.

| Phase              | PR                                                          | What it added                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------------ | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1 · Scaffold       | [#1](https://github.com/andrelkj/andrelkj.github.io/pull/1) | Pinned tooling, strict TypeScript, ESLint guards, Playwright config (375 / 768 / 1280), first smoke test, CI in the Playwright container.                                                                                                                                                                                                                                                                                                                                                                                                  |
| 2 · Infrastructure | [#2](https://github.com/andrelkj/andrelkj.github.io/pull/2) | `test` fixture with theme/lang seeding and a page error guard, page object with a locator contract, plus helpers for axe, overflow, i18n parity and links. Each helper has self-tests showing it can fail.                                                                                                                                                                                                                                                                                                                                 |
| 3 · Specs          | [#3](https://github.com/andrelkj/andrelkj.github.io/pull/3) | `docs/REQUIREMENTS.md` (30 IDs mapped to the site's QA claims) and 7 specs: a11y, theme, i18n, responsive, links, navigation, health. Every test carries its REQ-IDs. 37 deliberate site breakages (mutants) were each caught by the intended test, and the 2 that first survived led to stronger checks.                                                                                                                                                                                                                                  |
| 4 · Visual         | [#4](https://github.com/andrelkj/andrelkj.github.io/pull/4) | 12 screenshot baselines (first screen + full page, dark/light, 3 devices), generated in the Linux Playwright container and reviewed before commit. Color threshold tightened to 0.05 after mutants showed the default missed a token color and a corner-radius change. Repeating runs 10× in CI exposed 2 capture problems (Chromium rounding a 6948.23px page; a WebKit resize handler racing the tablet shot), and both are fixed: final ×10 run 120/120. New `update_snapshots`, `repeat_each` and `grep` inputs on the Tests workflow. |
| 5 · Coverage       | [#5](https://github.com/andrelkj/andrelkj.github.io/pull/5) | `docs/COVERAGE.md` generated from test annotations (each test linked to its line). The CI gate `coverage:check` fails on untested requirements, untagged tests, unknown IDs, stale "planned" markers and an out-of-date matrix. 6 unit self-tests; 4 real-repo mutants caught.                                                                                                                                                                                                                                                             |
| 6 · Mutation       | [#6](https://github.com/andrelkj/andrelkj.github.io/pull/6) | `npm run mutate`: 43 mutants (every defect proven by hand so far), each run on a temp copy of the site and scored as caught only by tests for the requirement it breaks. Crashes, stale mutants and survivors all fail the run. Mutation workflow weekly and on demand (~23 min, too slow per PR); `docs/TRUST.md` scorecard.                                                                                                                                                                                                              |
| 7 · Skills         | [#7](https://github.com/andrelkj/andrelkj.github.io/pull/7) | Six Claude Code skills (`qa-plan`, `pw-write-test`, `pw-review`, `pw-heal`, `a11y-triage`, `trust-audit`), shared conventions and review checklist, an exact WCAG contrast script, `CLAUDE.md` and Playwright's test MCP server. The stock Playwright agents were evaluated and rejected (their healer edits expected values). `pw-heal` dry-run on a real locator drift: contract, specs and mutants green after a page-object-only fix.                                                                                                  |
| 8 · Deploy         | [#8](https://github.com/andrelkj/andrelkj.github.io/pull/8) | Deploys gated on the full test workflow; post-deploy smoke once the live site serves the new commit; nightly real-network external-link check (REQ-LINK-06, all 31 requirements now covered) and live smoke; PR template with the human trust checklist. Full `pw-review` pass: fixed loops over locators that could pass vacuously (proven), plus two minor fixes.                                                                                                                                                                        |
| 9 · Skill evals    | _this PR_                                                   | With/without benchmark of the six skills (skill-creator workflow): 13 evals on seeded scenarios, 26 runs in isolated copies, scripts plus blind graders. With the skills 104 of 105 assertions passed, without them 98 of 105 (the baseline keeps `CLAUDE.md`). No `pw-heal` run edited an expected value, with or without the skill. One skill changed: `trust-audit` now probes defects outside the mutant catalog; its first run found two untested behaviors (reduced-motion hero text, header hiding with keyboard focus inside).     |
